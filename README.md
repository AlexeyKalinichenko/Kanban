# Канбан-доска на Flask (много досок)

## Запуск

1. Установите Flask и сервер waitress (если ещё не установлены):

   ```
   pip3 install flask waitress
   ```

   Без waitress приложение тоже запустится — на встроенном сервере Flask,
   но он годится только для проверки, не для работы через интернет.

2. Запустите сервер:

   ```
   python3 app.py
   ```

3. Откройте в браузере:

   ```
   http://127.0.0.1:5050
   ```

   Откроется стартовая страница — пространство гостя. Аккаунт создастся сам,
   как только вы что-нибудь сделаете (например, создадите доску).

### Настройки запуска (переменные окружения)

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `KANBAN_HOST` | адрес сервера; `0.0.0.0` — доступен из сети | `127.0.0.1` (только этот компьютер) |
| `KANBAN_PORT` | порт | `5050` |
| `KANBAN_THREADS` | сколько запросов обрабатывать одновременно | `16` |
| `KANBAN_SECURE_COOKIES=1` | cookie только по HTTPS (см. ниже) | выключено |
| `KANBAN_PROXY=1` | сервер стоит за обратным прокси (nginx, Caddy, Cloudflare Tunnel…) | выключено |
| `KANBAN_DEBUG=1` | режим разработки Flask: автоперезапуск при правке кода, отладчик | выключено |
| `KANBAN_ADMINS` | логины, которым открыта статистика `/admin`, через запятую | никому |

Например, доступ из сети: `KANBAN_HOST=0.0.0.0 python3 app.py`;
со статистикой для себя: `KANBAN_ADMINS=alexey python3 app.py`.

- `KANBAN_DEBUG=1` — только на своём компьютере: через отладчик Flask в
  браузере можно выполнить любой код на сервере.
- `KANBAN_PROXY=1` включайте, только когда сервер действительно за прокси:
  тогда адрес посетителя берётся из заголовка `X-Forwarded-For`, и
  ограничения «с одного адреса» считаются по настоящим посетителям, а не по
  адресу прокси. Без прокси этот заголовок может подделать кто угодно.
- Сервер работает **одним процессом** (потоков — сколько угодно): аккаунты
  держатся в памяти процесса. Не запускайте несколько копий над одной папкой
  `Data` (например, gunicorn с `--workers` больше 1).

## Страницы

- `/` — стартовая страница своего пространства: список досок, кнопка
  «+ Создать доску», удаление доски по крестику на плитке. Слева вверху —
  меню аккаунта. Ниже — раздел «Доступные мне» (чужие доски, к которым вам
  открыли доступ; виден, только если такие доски есть).
- `/board/<id>` — своя доска (`id` — GUID из имени файла).
- `/board/<id владельца>/<id>` — чужая доска, к которой открыт доступ (см.
  «Общие доски»). Удалённую доску или доску без доступа открыть нельзя —
  переход на стартовую страницу.
- `/login` — вход в существующее пространство по логину и паролю
  (кнопка «Войти» на стартовой странице).
- `/admin` — статистика по журналу событий (см. «Журнал событий»). Открыта
  только логинам из `KANBAN_ADMINS`, у которых задан пароль; у них в меню
  аккаунта есть пункт «Статистика». Остальным — «страница не найдена» (404).
  Цифры пересчитываются не чаще раза в 5 минут (кнопка «Обновить» — сразу).
  Краткая сводка в консоли: `python3 stats.py 30`.

## Аккаунты и пространства

- У каждого пользователя своё пространство досок, его имя — логин.
- Любой заход без входа (новый посетитель, после выхода, устаревшая cookie)
  открывает пространство гостя: на кнопке аккаунта — «Гость», на сервере при
  этом ничего не создаётся. Гость видит три шаблонные доски — «Дом»,
  «Пет-проект: трекер привычек», «Поездка в Грузию» (папка `templates/`):
  они показывают все возможности доски — цвет фона, приоритеты, теги (в том
  числе несколько на карточке и тег без названия), жирный текст, списки с
  вложенностью, чекбоксы.
- Аккаунт создаётся при первом изменении: задали логин, задали пароль,
  создали доску, изменили шаблонную доску (столбец, карточка, название,
  цвет, чекбокс…), удалили или переставили доски. В новый аккаунт копируются
  все три шаблонные доски (с теми же id — открытая доска остаётся на месте),
  и браузер сразу оказывается в этом аккаунте. Сами шаблоны не меняются.
- Перед этим первым действием гостю обязательно показывается окно «Как вас
  зовут?»: закрыть его, не введя имя, нельзя. Введённое имя становится
  логином (это и есть единственная смена логина), затем продолжается само
  действие (например, «Создать доску» → «Как вас зовут?» → «Новая доска»).
- Логин вида `user-4821` генерируется автоматически. Один раз его можно
  поменять на свой (меню аккаунта → «Сменить логин»; у гостя — «Ваше
  имя», тогда аккаунт сразу создаётся с этим логином). После этого логин
  больше не меняется, и пункт пропадает из меню.
- Логин: от 3 до 30 символов — русские или латинские буквы (но не вперемешку
  в одном логине), цифры, `-` и `_`. Уникален; при сравнении не важны регистр
  и «ё»/«е» (войти в «Алёна» можно, набрав «алена»). Логин, похожий на чужой
  до неотличимости (русский «ахеу» при латинском «axey»), занять нельзя.
- Пароль при создании не нужен. Дальше вход автоматический (cookie на год, продлевается при каждом заходе).
- Пока у аккаунта не задан пароль, на стартовой странице — начиная с третьего
  захода в аккаунт — висит напоминание «Задайте пароль, чтобы не потерять
  доступ». Заход — первое действие (открытие страницы, любое изменение) после
  перерыва не меньше 30 минут (перезагрузки и переходы между досками подряд —
  тот же заход); заход заканчивается, когда 30 минут нет действий; первый заход —
  создание аккаунта. Задать пароль раньше можно в меню аккаунта. Войти в пространство с другого
  устройства можно только после того, как задан пароль (не короче 6 символов).
- Меню аккаунта (слева вверху, на кнопке — логин): «Сменить логин» (пока
  его не меняли), «Задать/Сменить пароль», «Выйти» (у гостя «Выйти» нет).
  При смене пароля все остальные устройства выходят из пространства.
- Войти в существующее пространство — кнопка «Войти» слева вверху на
  стартовой странице, она открывает страницу входа. Кнопка есть только у
  гостя: как только аккаунт создан, она пропадает (чтобы войти в другое
  пространство, сначала «Выйти»). Если у пространства нет пароля, но есть
  доски, «Выйти» предупредит: вернуться в него будет нельзя.
- Пустые пространства без пароля, в которые не заходили 30 дней, удаляются
  автоматически (проверка раз в сутки). Пустое — без своих досок: нетронутые
  копии шаблонных досок не в счёт (как будто их нет).
- Защита от перебора: 10 неудачных попыток входа за 15 минут с одного адреса,
  не больше 20 новых пространств в час с одного адреса.

### Сессия и cookie

- Cookie `kanban_session` подписана секретным ключом из `Data/secret.key`
  (создаётся сам при первом запуске; не публикуйте его). Внутри — id
  пользователя, id устройства (для журнала событий) и версия сессий; версия растёт при смене пароля, поэтому
  старые cookie на других устройствах перестают действовать.
- Для работы через интернет по HTTPS запускайте сервер с переменной
  `KANBAN_SECURE_COOKIES=1` — cookie будут передаваться только по HTTPS.

## Как это работает

- Каждая доска хранится в своём файле в папке своего пространства:
  `Data/users/<id пользователя>/<guid>.txt`. Там же `boards-order.txt` —
  порядок плиток на стартовой странице.
- Аккаунты — в `Data/users.txt` (id, логин, отметка «логин уже меняли», хэш пароля, версия сессий, даты
  создания и последнего захода). Пароли хранятся только в виде хэша.
- Сервер читает `users.txt` один раз и держит аккаунты в памяти, поэтому
  скорость не зависит от числа аккаунтов. Новый аккаунт, логин и пароль
  записываются в файл сразу; время захода и счётчик заходов — пачкой, раз в
  несколько секунд, и при остановке сервера. Файл можно править вручную и
  при работающем сервере — он перечитается сам.
- Все файлы (доски, порядок досок, аккаунты) записываются атомарно: через
  временный файл, который затем подменяет старый, — половину файла никто не
  увидит, даже если сервер выключится посреди записи.
- Кнопка «+ Создать доску» создаёт новый файл с новым GUID и сразу
  открывает эту доску. Крестик на плитке удаляет файл доски (с подтверждением).
- Внутри доски каждое изменение сразу пересохраняет файл именно этой доски.

## Общие доски

Владелец может открыть доступ к своей доске другим пользователям — по логину
или по ссылке-приглашению.

- Кнопка «Доступ» (значок с людьми) в верхней панели доски, рядом с кнопкой
  фона. На кнопке — число пользователей, которым открыт доступ.
- Окно «Доступ к доске» у владельца: поле «Логин пользователя» и кнопка
  «Открыть доступ», ниже — список: владелец и те, кому открыт доступ; крестик
  в строке закрывает доступ. Логин ищется без учёта регистра, «ё» = «е», а
  похожие русские и латинские буквы не различаются (логины уникальны и по
  этому признаку, так что ответ однозначный).
- Доступ по ссылке — в том же окне, блок «Доступ по ссылке»: «Создать
  ссылку», затем «Скопировать». Кто откроет ссылку (`/invite/<секрет>`),
  получает доступ и попадает на доску:
  - вошедший пользователь — сразу;
  - гость (в том числе новый посетитель) — страница приглашения («Пользователь
    … приглашает вас на доску», название доски) → «Открыть доску» → окно
    «Придумайте себе уникальное имя» (создаётся аккаунт) → доска; есть
    ссылка «Уже есть аккаунт? Войти» — после входа человек возвращается по
    ссылке-приглашению;
  - владелец по своей ссылке просто попадает на свою доску.
- Ссылка на доску одна. «Заменить ссылку» выдаёт новую — старая перестаёт
  работать; «Выключить ссылку» — ссылки нет, пока её снова не создадут.
  Доступ, который уже получили по ссылке, в обоих случаях остаётся (закрыть
  его — крестиком в списке). Недействующая ссылка: гостю — страница «Ссылка
  не действует», вошедшему — такое же сообщение на стартовой странице.
- Ссылку видит и меняет только владелец. Секрет ссылки — 22 случайных
  символа (128 бит), подобрать его нельзя.
- Права одни для всех: видеть и редактировать доску (столбцы, карточки,
  название, фон, теги). Удалить доску и управлять доступом может только
  владелец.
- У того, кому открыли доступ, доска появляется на стартовой странице в
  разделе «Доступные мне» (на плитке — логин владельца). Окно «Доступ к
  доске» у него — только список участников и кнопка «Убрать у себя»; то же
  делает крестик на плитке. Снова открыть доступ сможет только владелец.
- У своих досок, открытых другим, на плитке — значок с числом пользователей.
- Владелец удалил доску — она пропадает у всех. Если доступ закрыли, пока
  доска открыта, при следующем сохранении произойдёт переход на стартовую
  страницу.
- Гость открыть доступ может: сначала, как при любом изменении, окно
  «Придумайте себе уникальное имя» и создание аккаунта. Получить доступ гость
  не может — у него нет логина.
- Аккаунт с общими досками (своими, открытыми другим, или чужими) при чистке
  пустых аккаунтов пустым не считается.
- Защита от перебора логинов: не больше 30 ненайденных логинов за 15 минут
  на одного пользователя.
- Пока доска сохраняется целиком: если двое правят её одновременно,
  сохранится версия того, кто сохранил последним, а чужие изменения видны
  после перезагрузки страницы (это будет исправлено следующим этапом —
  сохранением по отдельным изменениям и автообновлением).
- Хранение — `Data/shares.txt` (см. `shares.py`), одна строка — один доступ
  или одна ссылка:

```
SHARE owner=<id владельца> board=<id доски> user=<id получателя> at=2026-10-15T22:30:00
LINK owner=<id владельца> board=<id доски> token=<секрет ссылки> at=2026-10-15T22:30:00
```

  В файле — секреты ссылок: не публикуйте его (в `.gitignore` он уже
  исключён правилом `Data/*.txt`).

  Сама доска остаётся в папке владельца. Логины в файле не хранятся (логин
  можно один раз сменить) — только id аккаунтов.
- API: `GET /api/board/<id>/access[?owner=<id владельца>]` — кто имеет доступ;
  `POST /api/board/<id>/access` `{name}` — открыть доступ (только владелец);
  `DELETE /api/board/<id>/access/<id пользователя | me>[?owner=…]` — закрыть
  доступ (владелец — любому, получатель — только себе). Чтение и сохранение
  чужой доски — `GET/POST /api/board/<id>?owner=<id владельца>`;
  `GET /api/boards` возвращает и `shared` — доски раздела «Доступные мне».
  Ссылка: `POST /api/board/<id>/link` (`{"reset": true}` — заменить),
  `DELETE /api/board/<id>/link` — выключить; `GET /api/invite/<секрет>` —
  владелец и название доски, `POST /api/invite/<секрет>` — принять приглашение.

## Журнал событий

Создание аккаунтов, входы, выходы и заходы записываются в
`Data/logs/events-ГГГГ-ММ.txt` (новый файл каждый месяц, хранятся 12 месяцев —
`LOG_KEEP_MONTHS` в `events.py`). Одна строка — одно событие:

```
2026-10-12T08:50:13+03:00 account.create uid=3fa8… name=user-4821 gid=5e2a91c0 trigger=board_create ip=192.168.1.5 ua="Safari 18 / macOS"
```

| Событие | Когда | Поля |
|---|---|---|
| `guest.start` | новый браузер без входа (поисковые роботы не пишутся) | `gid`, `ip`, `ua` |
| `guest.prompt` | гостю показано окно имени — он начал первое изменение (один раз на гостя) | `gid`, `action`, `ip`, `ua` |
| `account.create` | первое изменение гостя создало аккаунт | `uid`, `name`, `gid`, `trigger`, `ip`, `ua` |
| `account.delete` | чистка удалила пустой аккаунт без пароля | `uid`, `name`, `reason=cleanup`, `age_days` |
| `session.start` | браузер получил cookie входа | `uid`, `name`, `sid`, `reason`, `ip`, `ua` |
| `session.end` | вход в этом браузере закончился | `uid`, `name`, `sid`, `reason`, `ip` |
| `login.fail` | неудачная попытка входа | `name` (введённый), `reason`, `ip`, `ua` |
| `visit.start` | первое действие после перерыва ≥ 30 минут (и создание аккаунта) | `uid`, `name`, `sid`, `visit`, `gap`, `ip` |
| `visit.end` | 30 минут без действий | `uid`, `name`, `sid`, `visit`, `started`, `ended`, `duration` |
| `board.share` | открыт доступ к доске (владельцем по логину или по ссылке) | `uid`, `name` (владелец), `board`, `to_uid`, `to_name`, `via=link` (по ссылке), `ip` |
| `board.link` | владелец изменил ссылку-приглашение | `uid`, `name`, `board`, `action` (`create`, `reset`, `off`), `ip` |
| `board.unshare` | доступ к доске закрыт | `uid`, `name` (владелец), `board`, `to_uid`, `reason`, `ip` |

- `uid` — id аккаунта, `name` — логин на момент события, `sid` — id
  устройства (cookie входа), `gid` — отпечаток ключа гостя (связывает
  `guest.start` и `account.create`; сам ключ не пишется).
- `action` у `guest.prompt` и `trigger` у `account.create` — что гость пытался
  сделать: `board_create`, `board_save` (правка доски), `board_delete`,
  `board_order`, `board_share` (открыть доступ к доске или создать ссылку),
  `invite` (принять приглашение по ссылке), `password`,
  `rename` (окно «Ваше имя» из меню).
- `reason` у `board.unshare`: `owner` (владелец закрыл доступ), `leave`
  (получатель убрал доску у себя), `board_delete` (владелец удалил доску).
- Воронка гостя: `guest.start` → `guest.prompt` → `account.create` (связь по
  `gid`); разница между двумя последними — сколько ушли на окне имени.
- `reason` у `session.start`: `create`, `login`, `password` (новая cookie после смены пароля).
- `reason` у `session.end`: `logout`, `switch` (вход в другое пространство в
  этом браузере), `password_changed` (пароль сменили на другом устройстве —
  пишется, когда это устройство обратится к серверу со старой cookie).
- `reason` у `login.fail`: `no_user`, `no_password` (у аккаунта не задан
  пароль), `bad_password`, `rate_limited` (адрес заблокирован после 10 неудач;
  пишется один раз за 15 минут). Пользователь в любом случае видит
  «Неверный логин или пароль».
- `visit` — номер захода, `gap` — минут с прошлого действия, `started`/`ended` —
  начало захода и последнее действие, `duration` — минут.
- `visit.end` пишется с опозданием: при следующем действии пользователя или
  фоновой уборкой (раз в час и при первом запросе после запуска сервера).
- Заход считается на аккаунт, а не на устройство.
- Время — с часовым поясом. Значения очищаются от управляющих символов и
  обрезаются; пароли, ключ гостя и cookie в журнал не попадают. Ошибка записи
  журнала не мешает работе приложения.
- Прочитать журнал из скрипта: `events.read_events("Data/logs")` — словари
  `{"time", "event", поля…}`, испорченные строки пропускаются.

## Формат файла доски

```
# Kanban board data file
# Формат: TITLE: <название доски>
#         TAGDEFS ... TAGDEF key=<ключ> color=<цвет> label=<название> ... ENDTAGDEFS
#         COLUMN: <название> ... CARD priority=<critical|medium|minor> [tags=<ключ1,ключ2,...>] текст ENDCARD ... ENDCOLUMN
TITLE: Доска

TAGDEFS
TAGDEF key=yellow color=yellow label=желтый
TAGDEF key=blue color=blue label=синий
TAGDEF key=green color=green label=зеленый
TAGDEF key=red color=red label=красный
TAGDEF key=tag-mtcj4k2gicn0 color=gray label=
ENDTAGDEFS

COLUMN: К выполнению
CARD priority=medium
Придумать идею проекта
ENDCARD
CARD priority=critical tags=red,yellow
Срочная задача,
может быть многострочной
ENDCARD
ENDCOLUMN

COLUMN: В процессе
ENDCOLUMN
```

### Теги

- У доски есть общий список тегов (блок `TAGDEFS`), доступный на всех
  карточках этой доски.
- По умолчанию 4 тега: жёлтый, синий, зелёный, красный.
- В меню карточки (⋯ → «Теги») список показывает все теги доски — клик по
  тегу добавляет/снимает его с текущей карточки (меню не закрывается,
  можно отметить сразу несколько).
- Кнопка **«+ Новый»** внизу списка запрашивает название тега (диалог
  подтверждения), затем предлагает выбрать один из 10 цветов — новый тег
  с этим названием и цветом сразу появляется в списке у всех карточек.
  Отмена или пустое название — тег не создаётся.
- Крестик рядом с тегом в списке удаляет тег из реестра доски целиком —
  он пропадает из меню и снимается со всех карточек, где был проставлен.
- Крестик на самом бейдже тега (на карточке, появляется при наведении)
  снимает этот тег только с этой карточки, не трогая реестр.
- На одну карточку можно повесить сразу несколько тегов. Теги задаются и
  меняются только через меню карточки — при создании карточки теги не
  указываются.
- Доступные цвета (10 штук): красный, зелёный, жёлтый, синий, серый,
  коричневый, фиолетовый, голубой, розовый, салатовый
  (red/green/yellow/blue/gray/brown/purple/cyan/pink/lime).
- Старые файлы с форматом до появления пользовательских тегов
  (`tag=red` в строке `CARD`, без блока `TAGDEFS`) по-прежнему читаются
  корректно — недостающий блок `TAGDEFS` подставляется автоматически
  (4 тега по умолчанию).

Файл можно смело редактировать вручную — при следующей загрузке доска
(включая её название) соберётся заново из его содержимого.
